# PRD: Motion-Mirror (дзеркалення руху руки на сервоприводі)

## A. Загальна ідея

Пристрій повторює нахил руки оператора на сервоприводі. Датчик MPU-6050 на кисті вимірює прискорення та кутову швидкість, мікроконтролер обчислює кут нахилу комплементарним фільтром і задає положення серво. Потенціометр регулює підсилення руху, кнопка вмикає й вимикає режим утримання (HOLD). Сценарії застосування: телеприсутність, реабілітація, дистанційне керування маніпулятором, де віддалена рука повинна повторювати рух оператора без тремтіння й помітної затримки.

Проєкт виконується на NUCLEO-C031C6 у симуляторі Wokwi (форма B).

## B. Функціональні вимоги

| ID | Вимога | Перевірка | Статус |
|---|---|---|---|
| FR-01 | При старті система виводить у UART самотест: по рядку на кожну перевірку у форматі `[SELFTEST] <назва> key=value result=OK/FAIL` та підсумок `summary pass=N fail=M`. | лог UART | виконано |
| FR-02 | Система ідентифікує MPU-6050 за WHO_AM_I = 0x68; при помилці датчика серво лишається в нейтралі (1500 мкс). | хостовий тест `test_sensor_missing_keeps_servo_neutral`, лог | виконано |
| FR-03 | Система опитує акселерометр і гіроскоп не рідше ніж 190 разів за секунду (номінально 200 Гц). | поле `samples` у `[LOG]` (виміряно 196-197) | виконано |
| FR-04 | Кути pitch/roll обчислюються комплементарним фільтром (α = 0,98). | хостові тести фільтра | виконано |
| FR-05 | Серво керується PWM 50 Гц з імпульсом 1000...2000 мкс для кута -90...+90 градусів. | логічний аналізатор, хостовий тест `test_angle_to_us` | виконано |
| FR-06 | Зміни кута менші за 1,5 градуса ігноруються (мертва зона). | хостовий тест `test_servo_deadzone` | виконано |
| FR-07 | Підсилення 0,5...2,0 задається потенціометром (ADC). | лог (`gain_x100`), хостовий тест | виконано |
| FR-08 | Кнопка перемикає режими LIVE/HOLD з антидребезгом 20 мс. | хостові тести, лог `[EVENT]` | виконано |
| FR-09 | Лог роботи видається раз на секунду у форматі `key=value` (цілі числа), придатному для автоматичного розбору. | лог UART | виконано |
| FR-10 | Затримка «рух IMU -> зміна PWM» менша за 50 мс. | логічний аналізатор: час між I2C-читанням і фронтом PWM | не виміряно (див. аналіз записів) |

Вимоги запису й відтворення траєкторії (FR записати/відтворити) вирішено не реалізовувати в межах ЛР2: це розширення для наступних робіт.

## C. Датчики і виконавчі пристрої

| Пристрій | Інтерфейс | Яку вимогу реалізує | Альтернативи й чому відкинуто |
|---|---|---|---|
| MPU-6050 | I2C, 0x68 | FR-02...FR-04, FR-10 (кут нахилу) | ADXL345: лише акселерометр, без гіроскопа (фільтр не працюватиме на швидких рухах); LSM6DS3: відсутній у Wokwi |
| Потенціометр | ADC (PA0) | FR-07 (підсилення) | енкодер KY-040: цифровий, потребує обробки переривань і не дає абсолютного значення; фоторезистор: не має зручного ручного керування |
| Кнопка | GPIO (PC13) | FR-08 (режим HOLD) | бортова кнопка B1: у Wokwi не інтерактивна, тому використано окремий компонент |
| Серво SG92R | PWM (TIM3_CH1, PA6) | FR-05, FR-06 (виконавчий пристрій) | крокові двигуни: потребують драйвера й не дають простого позиціонування |
| UART (VCP) | USART2 | FR-01, FR-09 (лог) | окремий USB-UART: не потрібен, є ST-LINK VCP |

## D. План тестування

| Вимога | Тест |
|---|---|
| FR-01, FR-09 | запустити симуляцію, перевірити формат рядків UART; `docs/captures/analysis.md` містить розкодований UART |
| FR-02 | хостовий тест із чужим WHO_AM_I; у Wokwi: змінити адресу/відключити датчик і перевірити нейтраль |
| FR-03 | виміряти `samples` у лозі за 1 с (результат 196-197) |
| FR-04, FR-06, FR-07, FR-08 | хостові тести `make test` (112 перевірок) |
| FR-05 | запис логічного аналізатора, виміряти період і ширину імпульсу для двох кутів |
| FR-10 | запис аналізатора: різниця в часі між завершенням I2C-читання і наступним фронтом PWM |
