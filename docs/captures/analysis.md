# Аналіз сигналів у PulseView

Для ЛР2 записав сигнали у Wokwi та перевірив їх у PulseView. Було два записи: `i2c-uart-boot.vcd` (4,610 с) і `pwm-two-angles.vcd` (9,758 с).

Підключення аналізатора:

| Канал | Сигнал |
|---|---|
| D0 | I²C SCL (PB8) |
| D1 | I²C SDA (PB9) |
| D2 | PWM сервоприводу (PA6) |
| D3 | UART TX (PA2) |

## I²C

У декодері PulseView вибрав SCL = D0 і SDA = D1. На скриншоті [i2c-decoded.png](i2c-decoded.png) видно звернення до MPU-6050 за адресою `0x68` і до регістра `0x3B`, з якого починаються дані акселерометра. Також видно байти даних, наприклад `00`, `40`, `EF`, `5C`.

Послідовність обміну: START → адреса пристрою → запис `0x3B` → STOP → START → читання даних → STOP.

Під час обміну такт SCL має період **10 мкс**, тобто частоту **100 кГц**.

Скрипт також знайшов довгі ділянки низького рівня SCL на початку симуляції:

- у першому записі — **4 паузи**, приблизно **50,45–50,52 мс**;
- у другому — **5 пауз**, приблизно **50,45–51,13 мс**.

Це незвичайні паузи, але лише з VCD неможливо точно сказати, чому вони з'явилися. Можливо, вони пов'язані зі стартом симуляції, тому не записую їх як доведену помилку датчика.

## PWM

PWM під'єднаний до D2. Відстань між початками імпульсів — **20 мс**, частота **50 Гц**.

| Вимірювання | Ширина імпульсу | Скриншот |
|---|---:|---|
| Початковий стан | 1499,904 мкс (≈1500) | [pwm-1500us.png](pwm-1500us.png) |
| Після зміни нахилу датчика | 1611,008 мкс (≈1611) | [pwm-1611us.png](pwm-1611us.png) |

Різниця — **111,104 мкс**. Отже, після зміни нахилу керувальний імпульс серво змінився. У другому записі є також проміжні значення під час переходу.

## UART

Для D3 додав декодер UART: RX = D3, **115200 бод, 8N1**. На [uart-decoded.png](uart-decoded.png) видно байти повідомлення `SELFTEST summary pass=8 fail=0`. Наприклад, `53 45 4C 46 54 45 53 54` — це слово `SELFTEST` у ASCII. Отже, в записаному фрагменті UART передає підсумок самотестування: **8 успішних, 0 невдалих**.

## Висновок

За записами підтверджено I²C-зв'язок з MPU-6050, UART-повідомлення і PWM 50 Гц зі зміною ширини імпульсу. Вимогу **FR-10** (затримка від зміни даних IMU до PWM менше 50 мс) поки не вважаю перевіреною: для неї потрібне окреме вимірювання моментів зміни даних та PWM.

Для повторного аналізу можна запустити з кореня репозиторію:

```powershell
python scripts/analyze_captures.py
```

Результат роботи скрипта збережено в `analysis_output.txt`. Сам скрипт визначає частоту SCL, паузи та параметри PWM; I²C і UART розшифровувалися у PulseView.
